# ENGINE AUDIT: CSRGO AI Video Studio Production Pipeline

**Audit Date**: November 15, 2026  
**Auditor**: Senior Full-Stack & Video Production Engineer  
**Scope**: End-to-end codebase inspection of CSRGO AI Video Studio production engine.

---

## 1. Executive Summary

A comprehensive architectural and line-by-line audit of the CSRGO AI Video Studio codebase was conducted to identify the root causes behind repeated visuals, identical soundtracks, conflated research facts, and superficial completion reporting. 

The investigation confirms that while individual services (Ollama, Kokoro TTS, Playwright, FFmpeg) functioned in isolation, the **creative production engine was decoupled from the rendering engine**. High-level storyboards and shot lists were generated and saved to SQLite/JSON, but the HTML5/Canvas rendering engine bypassed them completely in favor of a single hardcoded archetype loop that repeated across all scenes. Similarly, the procedural audio engine was locked to a static chord progression with a fixed random seed (42), resulting in identical soundtracks across unrelated projects. Finally, the research engine lacked temporal anchoring and incident identity filtering, causing it to merge the January 25, 2023 Microsoft outage with the November 12–13, 2026 Exchange Online incident.

## 2. Root Cause Analysis

### Question 1: Why did six different shots all use `system_architecture_graph`?
**Root Cause**: In `backend/services/script_service.py` (lines 100-111), the visual archetype is determined once for the entire project using basic substring checks:
```python
if any(w in t_lower for w in ["git", "version control", ...]):
    visual_archetype = "git_repository_simulation"
elif any(w in t_lower for w in ["agent", "agents", ...]):
    visual_archetype = "ai_agent_workbench"
elif any(w in t_lower for w in ["neural", "network", ...]):
    visual_archetype = "neural_network_layers"
else:
    visual_archetype = "system_architecture_graph"  # Default fallback!
```
Any topic not matching "git", "agent", or "neural" (such as "Microsoft Outlook outage") automatically fell back to `system_architecture_graph`.

Then, in `backend/services/visual_service.py` (lines 875-884):
```javascript
window.render = function(t) {
  if (archetype === 'git_repository_simulation') {
    renderGitSimulation(t, sc, p);
  } else if (archetype === 'ai_agent_workbench') {
    renderAgentSimulation(t, sc, p);
  } else if (archetype === 'neural_network_layers') {
    renderNeuralNetworkSimulation(t, sc, p);
  } else {
    renderSystemArchitecture(t, sc, p); // Executed for EVERY single scene!
  }
}
```
Because `archetype` was project-wide, `renderSystemArchitecture(t, sc, p)` was called on every frame of every scene. Every shot rendered the exact same central hub with 4 orbiting microservices (`API GATEWAY`, `DATA PIPELINE`, `STATE STORE`, `AUTH PROTOCOL`).

### Question 2: Were visual descriptions actually passed to the renderer or merely stored in the database?
**Root Cause**: Visual descriptions were stored in `storyboard.json` and inserted into the JavaScript `scenes` array, but **the Canvas rendering function completely ignored them**.
In `backend/services/visual_service.py`:
- `sc.visual_description` is never read by `renderSystemArchitecture`, `renderGitSimulation`, or `renderNeuralNetworkSimulation`.
- `sc.simulated_actions` is never read by the canvas drawing loops.
- `sc.camera_move` is completely unreferenced; no camera transformation (zoom, pan, tilt, FOV easing) was applied to the canvas context.
The renderer treated scenes as a flat text swap (`sc.narration` inserted into the bottom subtitle box) overlaid on top of a static, perpetually looping background animation.

### Question 3: Did the audio system generate a new score for every project or reuse a fixed file?
**Root Cause**: In `backend/services/audio_service.py`, the procedural music generator was hardcoded with a fixed random seed and a static chord progression:
- Line 9: `_rng = np.random.default_rng(42)`
- Lines 122–127: Static chord progression `Am - F - C - G` (A2, F2, C3, G2) at a fixed tempo of 112 BPM.
- Lines 150–165: A static arpeggio repeating notes `[0, 2, 1, 3]` across every project.
- Furthermore, SFX cues were generated by placing a single `whoosh` or `click` at scene transition boundaries (`project_service.py` line 274), completely ignoring on-screen events (no error sounds, no connection timeouts, no server hums, no recovery notifications).
Consequently, every generated video sounded virtually identical.

### Question 4: Why did research mix up the January 2023 and November 2026 Microsoft incidents?
**Root Cause**: In `backend/services/research_service.py`:
1. Search queries generated by Qwen did not specify an exact date window or incident identifier.
2. The search results from DuckDuckGo returned mixed historical articles for "Microsoft Outlook outage" spanning 2023, 2024, and 2026.
3. The prompt to Qwen simply said: `"Analyze these web research findings for the topic: '{topic}'"`. It lacked:
   - Event identity detection (`event_id` = organization + product + date + incident_id).
   - Temporal anchoring to filter out historical incidents.
   - Cross-checking of claims against primary sources.
   - Separation of preliminary incident communications from historical root-cause postmortems.
As a result, Qwen merged the historical January 25, 2023 WAN routing / BGP withdrawal incident (which affected 100M+ users across 180 regions for 90 minutes) into the story for the November 12–13, 2026 Exchange Online incident.

| **Visual Scene Renderer** | `backend/services/visual_service.py` | **Broken** | 4 monolithic hardcoded functions. Completely ignores scene descriptions, camera keys, and specific visual objects. Must be replaced with a modular Shot Compiler and multi-scene visual component registry. |
| **Audio Engine (Music)** | `backend/services/audio_service.py` | **Broken** | Fixed seed (42), fixed BPM (112), fixed chord progression (Am-F-C-G). Needs dynamic procedural composition adapting to topic, emotion, and scene progression using `templates/audio/music.py` and `dsp.py`. |
| **Audio Engine (SFX)** | `backend/services/audio_service.py` | **Incomplete** | Only transition whooshes/clicks at scene boundaries. Needs timeline event-based SFX (UI alerts, server hums, connection failures, recovery chimes). |
| **Audio Stems & Mix** | `backend/services/audio_service.py` | **Incomplete** | Outputs only single `mix.wav`. Needs multi-track stems (`stem_voice.wav`, `stem_music.wav`, `stem_sfx.wav`), `cues.md`, and automated ducking. |
| **Offline Voice Engine** | `backend/services/tts_service.py` | **Reusable** | Kokoro ONNX is functioning properly. Needs word-level timing precision. |
| **Quality Control Suite** | `backend/services/quality_service.py` | **Superficial** | Did not fail when visual subjects were identical across all shots. Must implement strict visual diversity checks, blank/frozen frame detection, audio stem verification, and factual claim validation. |
| **Master Orchestrator** | `backend/services/project_service.py` | **Reusable** | Needs integration of the new Research, Shot Compiler, Audio Stems, and Strict QC stages. |
| **Brand Asset Registry** | `backend/services/brand_service.py` | **Reusable** | Inline SVG vectors for major brands. Needs authentic Microsoft & Outlook interface assets and logos. |

## 4. Required Architecture Replacements

1. **Event-Anchored Research Engine (`research_service.py`)**:
   - Detect temporal scope (recent event vs historical concept).
   - Construct `event_id` (e.g. `MSFT-EXO-20261112`).
   - Query targeted date windows and official Microsoft status channels (`status.cloud.microsoft`, `@MSFT365Status`).
   - Emit `sources.json`, `claims.json`, `research.json`, and `research_report.md`.

2. **Visual Production Compiler & Multi-Scene Registry (`visual_service.py`)**:
   - Deconstruct videos into distinct scene components per shot.
   - For technical explainers / outage stories:
     - `Scene 1`: Realistic Outlook Mailbox Interface with frozen spinner & connection alert.
     - `Scene 2`: Multi-service Impact Dashboard (Exchange Online, OWA, Teams sync status).
     - `Scene 3`: Geographic & Service Scope Map with official incident timeline.
     - `Scene 4`: Infrastructure / NOC View with traffic routing bottlenecks.
     - `Scene 5`: Step-by-Step Traffic Redistribution & Service Recovery.
     - `Scene 6`: Architectural Resilience & Cloud Dependency Conclusion.
   - Apply shot-specific camera easing (push-in, pan, slow zoom, focus shifts).
   - Enforce distinct visual subjects across scenes.

3. **Dynamic Procedural Music & Event-Based SFX (`audio_service.py`)**:
   - Seeded by project hash (deterministic yet unique per project).
   - Dynamic key, BPM, and harmonic progression mapped to story emotional arc (Tension $\rightarrow$ Outage Escalation $\rightarrow$ Investigation $\rightarrow$ Recovery $\rightarrow$ Resolution).
   - Event-based SFX placed at specific on-screen event timestamps.
   - Separate audio stems: `stem_voice.wav`, `stem_music.wav`, `stem_sfx.wav`, `audio_cues.json`, `cues.md`.

4. **Strict Multi-Stage QC Enforcement (`quality_service.py`)**:
   - Frame-level visual uniqueness check comparing contact sheet frame hashes.
   - Reject any video where $\ge 2$ consecutive scenes share identical visual subjects.
   - Audio stem presence and loudness verification (-14 LUFS $\pm 1$ LUFS).
   - Factual claim validation check.
